# Web 七类经验训练、审核冻结与 A/B 测试

从报告库或 Codex 实验侧栏进入 **七类训练与测试**（`/experience`）。历史 **经验开发**（`/development`）继续只读展示研究归档，不启动历史脚本。若已运行旧服务，可重新双击根目录的启动器；它会更新空闲旧服务，保留活动实验。

## 开发训练

1. 流程选择“开发训练”，选择已登记案例，填写明确的模型 ID、分析与维护强度、反思强度及每会话超时。说明案例来源和历史暴露，点击“新建批次”。准备只捕获输入，不调用模型。
2. 点击“开始预分析”。模型只收到任务、候选源码及当前七类 codebook，输出候选 Contract、多标签、机制前提和未知。它不是标准答案。所有候选文件完整读取；非 UTF-8 文本候选明确拒绝，不静默省略。
3. 在页面对照源码审核分析 JSON、引用和义务方向。允许人工修正 JSON，原始模型输出保持不变。填写依据并确认核对；这是操作人的人工语义审核，不是独立评委核查。
4. 点击“开始训练”：先评分原始候选，再从原始候选独立运行两次 AUTO。AUTO 材料为任务、审核后的候选 Contract、共同提醒和对应七类提醒。若两次整题均通过，本批停止，不额外搜索经验。
5. 否则运行一次反思。反思只读取开发材料：原任务、完整源码、原始及两次 AUTO 行为评分、全部得失、补丁及公开回答。输出规则对象，逐条记录支持证据、保留义务、可证伪验证及因果状态。原因假设不能冒充已验证因果。正文由规则对象确定性渲染，经验仍为候选。
6. 在页面打开 `reflection-evidence.json` 和规则对象，逐条审核适用/排除条件、无据政策、应保留行为和反例。拒绝则停止；通过后点击“开始两次开发回验”。两次都从原始候选开始，仅追加这份固定经验正文。
7. 页面列出每次回验相对每份 AUTO 的新增通过、丢失和未知，同时保留相对原始候选的得失。至少一份比较存在新增通过才满足本版改善门槛；不要求两次整题全对，也不隐藏退步。无改善则停止，不能冻结或发起测试。
8. 达到门槛后人工点击“冻结研究经验”。这只固定本批研究条目，不是生产发布，也不代表已证有效。冻结后可以创建测试批次。

## 冻结经验 A/B 测试

1. 选择“冻结经验 A/B 测试”，选择冻结的开发条目与其他已登记案例，说明来源关系及暴露。禁止同一案例或完全相同源码及任务被用作迁移测试；不同 ID 本身仍不能证明来源独立。
2. 单独预分析测试输入，并只依据当前任务和源码审核。测试预分析不接收经验正文、开发反馈、标准评分或参考补丁。
3. 点击“开始 A/B 测试”。路由复用 `experience_routing.route`：先多标签匹配，再核对已知机制前提、被反证的排除条件及绑定当前输入的语义审核。最多选一条经验；未知或不适用回退 AUTO。
4. A/B 共享任务、原始候选、自动 Contract、类别提醒、模型、强度、权限和超时。B 仅在命中时追加原样冻结正文。固定顺序为 **B1 / A1 / A2 / B2**，四份独立副本，不继承补丁或会话。此顺序不控制模型采样。
5. 每份完整候选由既有可信案例评分器评分；先校准参考修复。页面同时展示整题、完整行为、相对原始候选损失、同重复 B 对 A 的得失，以及实际 CLI 会话用量和耗时。未知用量不补成完整总量，缓存不额外叠加。
6. 若回退，A/B 提示字节相同，页面明确提示差异不能归因为经验。测试阶段不调用反思，不更新经验，不将结果回流训练。

## 执行边界与归档

复用现有本地 Codex 执行器和登录；明确模型运行沿用 `--ignore-user-config`，不继承本地 MCP 配置。结构化分析和反思为 read-only，维护为 workspace-write。只有点击对应运行按钮才调用模型。Web 的独立工作区及提示约束不是严格文件读取隔离，因此本页结果标为探索性，不宣称正式盲测或独立泛化。

本版冻结模型、effort、单会话超时和会话次数，没有逐请求 hook 硬上限或逐请求计量；用量只来自 CLI 实际返回的会话字段。服务错误、超时、取消、结构不合法、评分无效或冻结材料漂移会停止后续阶段，保留原始日志和未启动槽位，不自动重试或续跑。正常行为失败继续完成当前阶段预定槽位。重启将无持锁运行器的活动批次标记为 interrupted。

默认归档为报告库相邻的 `<reports>-experience-v2/x-*/`：

- `protocol.json`：固定配置、来源说明、候选源码、评分文件版本及测试库快照。
- `input/`：候选原始字节及可执行权限。
- `jobs/j-*/`：初始提示、schema，以及 `execution/jobs/j-*/` 中的工作区、公开回答、事件、stderr、补丁和状态。会话评分位于各 execution 的 `evaluations/`。
- `analysis-raw.json`、`approved-analysis.json`：模型原文与带人工审核的分析，分别保存。
- `reflection-evidence.json`、`candidate-object.json`、`candidate-entry.json`、`candidate-review.json`：开发反思输入、规则对象、派生正文和审核。
- `development-admission.json`、`frozen-entry.json`：完整开发比较、门槛及研究冻结。
- `test-inputs.json`、`test-summary.json`：测试路由、确切 A/B 提示、分组和全部得失。
- `manifest.json`：可变阶段和执行日志，不加入冻结材料清单。

旧研究目录、旧失败记录、旧 A/D 条件、全局七类注册表及生产经验库均保持原样。实现不导入研究归档中的 Python 运行器。

## 本地验证

```sh
python3 -B -m unittest discover -s tests -p test_experience_workbench.py
node vscode-extension/test/experience-browser.cjs
```

浏览器检查沿用已有 Playwright 和本地 Chrome；必要时为现有安装设置 `NODE_PATH`，不会新增项目依赖。测试使用临时合成案例、模拟 CLI 和合成 oracle，只验证执行与展示链路，不代表模型收益。
