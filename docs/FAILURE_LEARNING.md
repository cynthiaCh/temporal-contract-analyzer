# 基于失败反馈的候选经验与检索更新

## 具体失败假设与同补丁修复对照（v2）

已评分失败任务现在可以从**实际被评分的补丁快照**继续，创建两个独立副本：当前补丁重新扫描后的 D（`review`）与同一 D 加具体失败假设（`hypothesis_review`）。网页结果行点击“准备修复对照”，检查新实验后再启动；准备本身不调用模型。CLI 支持直接准备或显式运行：

```sh
python3 -B -m temporal_contract_analyzer reports repair EXPERIMENT_ID \
  --job j-002 --store /path/to/reports --node /path/to/node
# 增加 --run 才会调用模型并等待两组评分。
```

两组继承父任务显式模型、推理强度、配置路线和单次超时，各运行一次。本地默认配置只继承当前配置路线，不能证明仍与父任务当时解析出的模型和强度相同；本次 11 组对照均使用显式覆盖。新增材料不同，所以 token 数不等量；实际用量另行记录。控制组也从同一补丁继续，不是原始 base 的新一次 D。顺序按父实验 ID 奇偶交替，不宣称随机化。

`hypotheses.json` 为每个失败必需效果或违反的禁止效果生成原因候选、预测执行顺序、可反证步骤及来源。允许在开发条件中向假设组披露失败效果标识和极性；不披露隐藏期望载荷、测试实现或 reference。候选原因从有限故障家族生成，结合当前补丁按标识符检索定位，再补已解析的直接调用者、词法定义、本地导入和状态标识符出现位置。调用关系限可解析的标识符调用；对象成员派发、动态回调流和业务所有权不自动成为已证明事实。未分类反馈、证据不足、解析缺口与预算遗漏明确保存。模型需用候选可见代码构造复现以验证或反证假设；业务契约无法从可见材料确定时应报告歧义。

评分后 `evaluation.regression` 分别列出 `gained`、`lost`、`remaining_failed`，涵盖必需效果成立和禁止效果不发生两种检查。任何丢失原通过项的候选均 `eligible=false`；不以净增数抵消退步，也不自动覆盖父补丁。无退步仅表示可供复核，`fully_repaired` 还要求整体 PASS。oracle、案例版本、运行时或明确布尔字段不一致时，比较为 unverified。旧评分及 v1 经验功能保持原样。

批量对照可以使用 `tools/run_repair_comparison.py --matrix RESULTS_JSON --output NEW_DIRECTORY --bench-root BENCH --node NODE --execute`，仅选择导出表中的原 D 失败组。输出准备与结果索引、逐项新增/丢失效果、用量和比较 Markdown；不带 `--execute` 仅准备。新实验追加到父实验所在报告库的实验档案中，研究汇总位于新输出目录。

## 早期经验辅助（v1）

首版实现“校准后的失败 → 候选经验 → 显式开发重试”。它更新的是经验记忆和检索优先级，不会自动发明或发布静态分析规则，也不会训练模型。

## 运行方式

新实验完成行为验证后，只有参考修复校准 PASS，且正常完成的 Agent 补丁被评为语义失败，才会自动提炼经验。超时、进程错误、参考校准失败不作为语义失败学习。提炼失败另记 learning-error.json，不更改原验证结果。

旧实验可点击结果页 **从失败提炼经验**，或运行：

```sh
/usr/bin/python3 -B -m temporal_contract_analyzer reports learn EXPERIMENT_ID
/usr/bin/python3 -B -m temporal_contract_analyzer reports lessons \
  --case-id transfer-progress-composition-v4-vanilla
```

经验保存在报告库的 `lessons/l-*.json`，与不可变扫描目录、原始实验和评分分开。每个实验/验证版本生成一个稳定 ID；重复提取复用相同内容，不覆盖旧经验。

## 后续如何使用

1. 选择同一案例，在“其他报告条件”勾选 **失败经验辅助（开发）**。
2. 系统仅匹配相同 case ID、相同候选文件字节清单及任务文本的最新 3 条候选经验；源文件或任务变化时拒绝无匹配的条件。文件权限、模型和 oracle 版本不是匹配键，适用性仍需核查。
3. 新建独立条件 `learned_review`：原 D 报告 + 候选核查问题 + 当前归档快照的源码检索片段；因此要求 D 有实质源码发现。A/D 及其他冻结层保持原义。
4. 新实验保存经验 ID、学习条件说明、learned-context.json、确切 report.md/prompt.md 与已有摘要；启动时检查冻结材料未被修改。准备不调用模型，点击开始才调用。

这是同任务反馈暴露后的开发重试，不能当作盲测、未见项目泛化或与原 A/D 同等未暴露的样本。若研究要比较基线，也应把“已有失败反馈可用”作为实验条件明确控制；本地工作目录和 prompt 不是严格文件系统隔离。

候选经验文件损坏时，历史实验仍可查看，页面提示经验暂不可用；原 A/D 仍可准备。需要经验的条件会明确报错，避免静默遗漏经验。自动提炼的异常单独记录，不改变已完成的评分。

## 首版实际学习什么

实现是确定性的，不调用 LLM：

- 已评分失败中的断言名称包含 audit/history/record 时，选用“分别核查历史记录与当前显示的有效性条件”候选策略。
- 所有已评分语义失败增加“补查暂停、重入、清理、重试与后续访问的组合”候选策略。
- 策略是有待验证的核查问题，不把失败名称当作业务契约或已证明根因。原始反馈的场景/断言 ID 仅保存在研究者侧经验 JSON 中，不把 oracle 期望值、失败列表或 reference 补丁塞进 Agent 的新增材料。

检索使用当前扫描快照及已有函数范围，按 recording/audit/history/save 与 receive/show/display/render/publish 等标识符家族查找候选片段。优先补原报告未选中且同时涉及两类效果的文件，再补原有证据附近。函数内命中优先包含顶层函数，其他命中取邻近行；相邻片段合并，源码正文上限 6000 字符，超预算的完整片段列入 omitted。

这属于词法家族与源码范围检索，不是完整的调用方/回调实参数据流恢复；注释和名称也可能产生候选。未知关系、无匹配与预算遗漏仍需 Agent 回到仓库核查。

## transfer-progress 示例

`e-17fd00c46db24e49` 的 A 为 9/10、D 为 5/10；D 额外失败都涉及审计。经验提炼后，策略检索会额外找到 src/queue.js 中 recordProgress 与 showProgress 的不同条件，帮助后续审查显式比较两类效果的生命周期。

这只证明反馈选择与源码交付链路已接通；是否改善下一次修复，需要实际模型对照和行为验证。经验仍标记 candidate，不因生成成功或一次 PASS 自动成为通用规则。

## 迁移

跨电脑复制报告库与其相邻的 `-experiments` 目录时，`lessons/` 随报告库一起复制。启动脚本会检查 failure_learning 能力标记，只更新空闲旧服务；活动实验不会被自动中断。
