# 两例经验演化与同机制验证计划

**问题**：以前选例混用了裸任务难度、不同模型和不同来源的证据，尚未清楚验证从一个失败案例学到的经验是否帮助另一个同机制案例。
**方法**：标准 Contract 留在评价侧；执行 Agent 自主提取候选 Contract；只利用训练例的差异反馈生成一份通用修复经验；冻结后在另一个同源案例上对照。
**状态**：仅计划；0 新模型调用，未实现或启动运行器。

## 主张和边界

唯一待检验主张：在相同自动 Contract 流水线中，训练例产生的新经验能否增加另一个同源变体的完整修复，并保留原正确行为。排除仅因为输入 Contract 不同、模型不同或预算不同造成的差异。

两例只能作机制试验。三次重复不是三个独立案例，不宣称统计显著、跨来源泛化或普遍有效。训练指经验／提示文本更新，不修改模型权重。

M2 基线不能混入 M4 正式分母。即便复用历史基线，也必须核对完整 prompt、Contract、起点、模型、effort、工具和预算，不能只因 case ID 相同就视为配对。新抽取的 Contract 不同时，旧失败仅供选例参考。

验证筛查只用于预先选择有观察空间的任务；验证题的标准、轨迹、补丁和分项失败不提供给反思器。训练程序在独立输入目录中运行。当前作者已经了解案例且来源相关，隔离未来会话不能把它变成独立未见测试。

## 结果如何判断

首要指标是完整任务通过数、目标行为和已通过项保留；逐项行为向量、额外无据变更与所有阶段成本同时报告。

- AUTO 全过：该小样本未观察到修复提升空间，不判经验无效。
- 两组都失败：未观察到收益；结合失败关系判断经验不适用、落实不足或验证覆盖不足，不能仅凭总分指定原因。
- 新经验组改善：只记该同源小样本的观察收益；三次重复不证明稳定性或独立泛化。
- 已有行为退步：单列，不能用目标项修复掩盖。
- 政策、执行或评分不可信：结论为不可判定，不能记成行为失败。
