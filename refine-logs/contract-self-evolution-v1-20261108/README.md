## 一页看懂现在做什么

> 在同一类、对目标模型确实有难度的任务上，固定一份自动 Contract，检查追加 E1 是否改善修复。

| 项目 | 本批固定值 |
|---|---|
| 修复模型 | `gpt-5.6-terra / medium`，两组一致 |
| Contract 提取模型 | `gpt-6-sol / low`；只为准备公共材料，不是对照变量 |
| 对照 | `AUTO` 自动 Contract；`AUTO_E1` 相同 Contract＋原样 E1 |
| 经验位置 | 只在修复阶段追加；不增强提取 |
| 案例范围 | `download-polling-restoration` 同 cluster 派生任务，准确身份仍需登记确认 |
| 选例依据 | 相同修复模型及自动 Contract 流程的有效失败，不拿 Qwen 失败或原始代码校准失败代替 |
| 正式规模 | 最多 2 个案例，每组每例 3 次，共最多 12 次维护 |
| 当前状态 | 尚未确定符合要求的正式案例；不能声称已经准备好开跑 |
| 本轮是否学习新经验 | 否，固定 E1 的效果试验，不是新的自演化训练 |
| ReAct / GEPA | 不新增实验性控制器，不运行 GEPA；另批研究 |

先读 [统一计划](EXPERIMENT_PLAN.md)，再看 [进度表](EXPERIMENT_TRACKER.md)。机器可读规划值见 [protocol.json](protocol.json)，选例登记见 [case-selection.csv](case-selection.csv)。JSON 是计划记录，**不是已实现的运行器接口或可执行启动配置**。

## 不再混用的东西

- 不将 6-sol/low、Terra/medium、Qwen 的结果合为一个模型分母。
- 不将裸任务失败等同于自动 Contract 条件失败。
- 不把读文件失败、服务断流、预算截断算作行为失败。
- 不把报告关系描述更完整直接称为 Contract 增益或修复收益。
- 不把已有题库检索、固定追加 E1、官方 GEPA 搜索统称为同一次自演化实验。
- 不启动旧的 80/160 槽计划；本目录不自动恢复任何历史批次。
