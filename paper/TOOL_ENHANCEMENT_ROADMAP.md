# ICPC 2027 Tool Track：工具增强路线图

日期：2026-10-29。依据：当前源码、真实工作台截图、127 项 Python 测试、9 项插件 runner 测试、两版合成示例。**本文是增强方案；除稿件、示例和研究材料外，本次未修改分析器功能。**

## 核心判断

最值得增强的是：把“为何值得审查、哪些关系已有证据、哪些仍待人工确认”展示得更具体，并用独立实例测量这些材料是否帮助回答时序问题。继续扩大语言范围或增加共现规则，暂时不是主要投入方向。

当前最清楚的产品贡献是四问卡片，科研贡献候选是“对跨边界的有效性问题组织证据”。后者必须通过相关工作比较与理解任务评估才能成立，不能从功能数量推出。

## 方向 A：让线索依据成为审查界面的第一层信息

**当前依据**：`core.enrich()` 已在调用上记录 `api_basis`、`binding`，候选调用关系有 `basis` 和 `qualification`；`lifecycle.py` 明确采用词法命名空间的共现；`boundary_cards.cards()` 主要重组 finding 已有的 evidence。

最小实现应复用这些字段，在相关证据旁展示“名称线索”“同作用域共现”“局部源码顺序”“候选词法/导入绑定”。它们描述证据来源，不是可排序的正确性等级。不必新增数值评分器。

验收示例：两个不同对象恰好都有 close/publish 方法时，界面能解释候选的产生依据，并保留实例关系待确认。具有局部 guard 的示例能看到 guard，但不会自动标记 protection sufficient。

实施位置：`core.py`、`boundary_cards.py`、`web/app.js`；若修改报告 schema 或规则实现，新建分析批次，旧冻结材料继续按原版本读取。

## 方向 B：先改“证据覆盖”，再考虑推断保护

本次示例暴露了有价值的产品行为：两版代码都有 3 条提示，但 guard 证据不同。后续可增强卡片，让用户容易回答：

1. guard 比较的是哪一个局部变量？
2. 它是否在等待前捕获、在效果前检查？
3. 边界操作是否写入了被比较的状态？
4. 哪些连接有源码支持，哪些因别名、对象实例或路径条件而未知？

只做有界关系证据，先不做全程序 CFG、通用 points-to、框架调度解释器或自动修复。上述问题在当前规则中仍可能只部分覆盖，不能将拟议功能写进当前版论文。

**有意义的验收用例**：有效 epoch guard；检查了无关变量；guard 在 effect 之后；同名变量遮蔽；另一对象的 epoch；关闭后重开；被保护的 publish 和未保护的第二种 effect。验收关注证据关联和明确的 unknown，不要求工具给出全局安全判决。

## 方向 C：以时序理解任务证明工具价值

### 最小实例集

- 在规则开发之外选择固定版本的项目，优先 JS/TS/Vue 的真实维护场景；Python 可作为补充，避免三周内铺得过广。
- 预先记录项目与实例选择、排除标准；分别记录开发用与 held-out 实例。
- 每条关系记录 boundary、continuing work、identity/owner、effect、requirement evidence、protection 和缺失信息。
- 标注“关系成立”与“缺陷”分离；关系成立但保护充分，是有效审查实例。
- 人工独立复核后记录分歧与处理过程。没有行为见证的项目保留 unknown，不用规则输出生成真值。

### 对照设计

优先比较同一任务的三个视图：

| 条件 | 材料 | 主要回答的问题 |
|---|---|---|
| A | 源码与常规导航/搜索 | 无工具辅助的理解基线 |
| B | 相同源码与原始 finding、引用、限定条件 | 位置与事实本身提供多少帮助 |
| C | 与 B 相同的事实，加四问组织和核查流程 | 卡片组织是否额外提供帮助 |

若 C 增加了 B 不具备的信息，就不能把全部差异归因于布局；需要记录信息差异，或将问题文本也提供给 B。用户若填写历史人工意见，各条件必须明确是否包含，避免将人的答案误算成工具贡献。

主指标：时序问题回答正确率、关键关系遗漏、把充分保护误判为不足。次指标：完成时间、查看文件/位置数、主观负担。按参与者和任务处理重复测量，报告效应与不确定性；小规模便利样本仅称 pilot，不宣称广泛有效。人类参与者研究在招募前按机构要求完成适用审查与同意流程。

若无法在截稿前完成研究：正文保留实现与案例证据，准确描述评估尚未完成，接受竞争力较弱这一现实；不使用模型自评冒充开发者实验。

## 方向 D：公开交付与英文演示

- 当前 `setup.cfg` 没有完整包含 CLI 依赖的 Node 解析器运行资源；三周内优先验证现有 VSIX 或源码包路径，完整 wheel 可后置。
- 给英文使用者提供 scan → card → source → judgment → compare 的最短路线；E/T/L/H 和 B–G 分层放高级说明。
- 在录制前让一位没有参与开发的人从空环境安装并完成示例，保存遇到的配置错误；这支持安装可用性，不能单独支持理解收益。
- 至少核查一个干净环境；仅在实际验证后标注 Windows/Linux 支持，不将本机 Python 测试当作跨平台验收。
- 官网只要求源码或二进制公开，Marketplace 和完整开源源码并非必要条件。是否开源和许可证由作者决定，本次不替作者公开或选证。
