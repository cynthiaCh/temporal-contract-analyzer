## 人工变体是什么

仅在普通调用分支中，把以下 L30–31 的顺序：

```js
called = true;
return fn.apply(this, arguments);
```

改为：

```js
var result = fn.apply(this, arguments);
called = true;
return result;
```

接收者分支和其他代码保持不变。运行时 `fn` 同步调用自己的包装入口一次，原版只执行一次，变体执行两次；随后微任务再次调用和普通顺序重复调用仍只执行一次。精确差异保存在 `run-01/synthetic-order.patch`。

这份变体由研究者构造，**不是上游真实缺陷或维护者修复**。其测试结果只有一个引入的失败，不算多个独立发现。

## 为什么 0.6.3 没有识别出变化

普通调用中的 `called` 判断嵌套在 `if (this == global)` 里；当前入口状态分析只选择直接层的 guard，不建立这条嵌套分支路径。新增加的分支规则针对“被调用的外层参数本身在调用后清空”，也不覆盖此处独立布尔标志。接收者分支使用 `this[key]`，同样超出了当前裸变量状态绑定检查。

因此，新例显示的下一项需求是：有界嵌套路径与独立标志的顺序分析，同时保留接收者条件，避免拼接互斥路径。0.6.3 检查轮仅测试、不实现扩展；0.6.4 的实现和限制见本文顶部及工具说明。
