## 原版做什么

before(N, fn) 返回一个包装器，最多执行 fn N−1 次，随后返回缓存的结果。before(2, fn) 因此最多执行一次；before(3, fn) 最多执行两次。源码的关键顺序是：

```js
if (--times > 0) {
  memo = func.apply(this, arguments);
}
```

--times 在比较和用户调用之前完成。times 初值为 2 时，外层调用先把它降到 1；若回调立即重入，内层再降为 0，条件不成立，不会重复执行。

## 人工变体做什么

```js
if (times > 1) {
  memo = func.apply(this, arguments);
}
--times;
```

比较的是递减前的旧值，所以阈值从 >0 调整为 >1，并把递减推迟到 if 之后。对本次测试的有限整数、正常顺序调用，这保留了原来的 N−1 次限制；但同步重入时仍看到旧预算 2，又进入一次。

这不是单纯移动一整行：原来的前置递减位于条件表达式内，因此需要同时调整比较阈值。精确差异见 run-01/synthetic-order.patch。异常后的预算状态和对象到数字强制转换等情况未测试，不声称两个程序只在重入时有差别。

变体由研究者构造，**不是上游真实缺陷、历史修复或维护者确认问题**。这里只复现一个人工时序退化，不作为多个独立缺陷或一般 precision/recall 数据。

## 0.6.7 的覆盖边界

解析成功，原始语法事件可看到 --times；但当前状态发布规则主要分析简单状态写入/清空以及已支持的 guard 路径，没有关联这里的数字次数约束、条件内自减与外部调用。func 的后续清空又位于 if (times <= 1) 条件中，也不属于已支持的简单线性尾部清空模式。原始 findings 为空，问题不在默认报告筛选。

0.6.7 检查轮只测试；0.6.8 的受限识别改进见本文顶部，候选原版仍未修改。需要支持这种场景时，应保留比较/递减的实际求值顺序与分支条件，不宜只按 -- 名称或行号报警。
