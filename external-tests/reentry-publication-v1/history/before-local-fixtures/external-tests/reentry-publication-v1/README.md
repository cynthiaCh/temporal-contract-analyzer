# 真实重入案例：修改提取器后的效果

本轮只验证一类候选关系：调用用户函数之前，入口读取的闭包状态是否已经被写入。开发范围和限制见 [实现说明](../../docs/STATE_PUBLICATION_REVIEW.md)。

直接查看 [前后对照 HTML](run-06/comparison.html)、[结果 JSON](run-06/summary.json) 或 [新报告 D](run-06/before/bundle/review.md)。

| 已知上游版本 | 旧工具 | 新工具新增的具体关系 | 原有测试 | 上游新增重入测试 |
|---|---|---|---:|---:|
| 错误父提交 | 3 条宽泛提示，没有明确定位关系 | 用户调用先发生，状态赋值随后完成 | 80/80 | 0/3 |
| 维护者修复提交 | 同样 3 条宽泛提示 | 状态写入在用户调用之前 | 80/80 | 3/3 |

新工具仍保留原有提示，总数两版都是 4 条；改进体现在关系、源码引用和对照变化，不在提示数量。调用前写入也不等于写入值正确或程序安全。

错误版依据是第 103 行的入口判断、第 124 行的用户调用与从第 118 行开始的赋值。赋值右侧立即执行函数先运行，所以不能按文本起始行把赋值误认为已完成。修复版在第 121 行写入状态，第 129 行调用用户函数。

`run-06` 的 11 项开发输入均匹配明确列出的预期：包括真实前后版本、改名和格式变体、延后执行、变量遮蔽、条件写入与 undefined 写入。条件写入为未知；undefined 写入只报告顺序，不判定保护充分。变体都是已知开发对照，不是 11 个独立缺陷，也不是准确率或未见验证集。专项测试另覆盖审计发现的兄弟函数改写、解构成员赋值、块级/catch/类声明遮蔽、类初始化与命名函数表达式内部绑定。

`baseline/` 在改代码前冻结了旧报告和相关旧实现；`run-01/` 至 `run-05/` 是开发中的历史运行，不覆盖，当前结论使用 `run-06/`。当前运行还保存本次实现副本及摘要。跨工具版本不直接计算 hint delta；对照 HTML 使用同一新工具分析的两个上游版本。

原始来源是相邻 bench 中固定的 p-debounce 修复 e7dfeb6563390ee677ae0d7e402ae88cdafab622 及其父提交，MIT 许可证和完整出处保留在 `../temporal-contract-bench/studies/p-debounce-real-fix-v1/`（相对于分析器仓库根目录）。分析器只接收 index.js；测试由外部执行器单独运行。没有调用 LLM，没有测量其修复收益。

从分析器根目录复跑，需要已有的相邻 bench 资料、Node >=22 与解析依赖，不安装新依赖：

```sh
python3 -B external-tests/reentry-publication-v1/run.py \
  --output external-tests/reentry-publication-v1/run-new
```
