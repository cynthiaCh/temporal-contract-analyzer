本轮给出 12 个非时序方向，全部保留，不排序。它们面向程序理解，不依赖现有 analyzer，也不局限于前端。N1、N6、N9、N10、N11 明确覆盖科学计算、数据处理、插件和编译系统；N3、N10 是高风险、高收益方向。

共同假设：以开发者选定的输入、观察边界和显式需求为依据；差异本身不等于缺陷。工期是单人专注工作日估算，默认只做一个语言或框架的可演示原型。下面的 CPU pilot 均为待执行方案，不是已有结果；没有实现代码、运行实验、调用付费 API、使用 GPU 或安排用户研究。“差异假设”均未完成系统查新。

**N1｜数值含义护照：这个数字沿途究竟表示什么？**

- **问题与最小例子：**传感器的 `-32768` 明确表示缺测，其他整数按 `raw / 10` 转为摄氏度；程序先换算，再用原始哨兵值过滤，缺测值因此进入平均数。开发者想知道：一个数从输入到结果，单位、比例和特殊值含义在哪里改变？**输入：**Python 数值处理函数、少量样本，以及用户确认的单位／哨兵声明。
- **机制，三步：**①从显式声明建立“有效值域、单位、哨兵分支”；②沿受支持的赋值、仿射换算和过滤操作传播这些含义；③为首次失配生成一个原始输入和完整计算路径。**三分钟演示：**点击异常平均值，看到 `-32768 → -3276.8 → 被计入均值`，再看到有效值 `0` 的不同路径。
- **近邻与待验证差异：**[Checker Framework Units Checker](https://checker-framework.org/manual/#units-checker) 已检查单位一致性。待验证的是把单位变换和“特殊值何时变成普通值”合成一个可回放的解释单元；不能把普通单位检查当创新。**最大阻碍：**未声明的领域含义无法可靠恢复；名称只是搜索线索。**工期：**6–9 天，仅 Python 标量、仿射变换和过滤。
- **最便宜证伪：**手写 12 个小管道，CPU 运行预算 30 分钟。正控为先换算后错误过滤；负控为先过滤、显式换算哨兵、以及有效零值。若工具无法同时说明有效零值为何保留、哨兵为何流入，就没有证明解释能力。

**N2｜配置反事实：改哪一项，程序才真的换实现？**

- **问题与最小例子：**YAML 写 `backend=cuda`，命令行覆盖为 `cpu`；改 YAML 没作用。开发者想问的不仅是最终值来自哪里，还包括：允许修改哪些层时，怎样才能实际选中另一个实现？**输入：**一个确定启动命令、配置文件、已有框架解析结果，以及实现注册表。
- **机制，三步：**①记录真实解析过程中的覆盖和插值依赖；②连接最终配置与实际选中的实现；③在用户允许修改的配置位置内搜索最小改动，并重新解析验证。**三分钟演示：**展示“这项修改被命令行覆盖”，随后给出“删去此覆盖或修改此参数可选中 CUDA”的可复现配置差异；不擅自修改环境。
- **近邻与待验证差异：**[Hydra #2991](https://github.com/hydra-ecosystem/hydra/issues/2991) 涉及现有导航能力和逐节点来源需求；[Microscope](https://conf.researchr.org/details/icse-2025/icse-2025-research-track/87/Datalog-Based-Language-Agnostic-Change-Impact-Analysis-for-Microservices) 已联合分析代码、配置和框架。差异假设是“受编辑范围限制、经重解析验证的实现切换方案”，来源展示本身不新。**最大阻碍：**自定义 resolver 或副作用使配置不可纯重放。**工期：**6–8 天，限定 Hydra 的纯配置和显式注册表。
- **最便宜证伪：**8 组配置，每组 4 层覆盖，CPU 预算 30 分钟。正控包含多处遮蔽；负控包含同值覆盖和不参与选择的参数。若建议改动没有改变所选类，或把无关参数列为必要修改，核心假设失败。

**N3｜业务行为地图：同一个输入，究竟会在哪些入口得到不同处理？〔大胆方向〕**

- **问题与最小例子：**三个入口都调用或实现资格判断，其中两个接受 `amount >= 100`，一个接受 `amount > 100`。不预设谁错，直接问：这些入口把输入空间分成了哪些共同区间，分歧集中在哪里？**输入：**开发者指定的同义输入映射、三个可执行入口、显式有效输入范围；不按字段标题猜业务一致性。
- **机制，三步：**①抽取影响指定结果的条件，保留源文件位置；②在受限整数／枚举域中联立各入口条件，形成“各入口结果向量相同”的区域；③为每个分歧区域生成最小见证，并回放验证。**三分钟演示：**地图只有一条边界 `amount=100`，点击后并排显示三个返回值和造成差异的条件。
- **近邻与待验证差异：**[SIRNA](https://arxiv.org/abs/2608.00396) 已做业务规则的可验证一致性检查；[SymDiff](https://www.microsoft.com/en-us/research/project/symdiff-differential-program-verifier/) 已验证程序间关系。差异假设是把多个入口的实际行为整理成可浏览的共同分区，而非只报告相对某条规则的违例；这可能是理解工作流贡献。**最大阻碍：**入口参数对应关系和外部状态通常比求解更难。**工期：**9–12 天可做三个无外部状态的 Python 入口；1–2 个月尝试真实业务规则子系统。
- **最便宜证伪：**6 组三入口谓词，每组人工列出完整有限真值表，CPU 预算 1 小时。正控为边界和组合条件分歧；负控为不同写法但等价的谓词、显式不重叠的适用域。若分区不能与真值表一致，或无法保持输入域限制，就不能支持后续扩展。

**N4｜断言观察地图：这个测试究竟排除了哪些错误结果？**

- **问题与最小例子：**测试执行了全部查询代码，但只断言 `len(rows)==2`；记录 ID、内容或顺序改变仍通过。开发者想知道“测试保护了什么性质”，而不只是执行了哪些代码。**输入：**一个 pytest 测试、结果生产函数、用户指定的结果维度和有效结果约束。
- **机制，三步：**①把断言对结果的读取与变换提取出来；②在有效结果约束内生成改变成员、顺序或数值等单一维度的候选，并用受限生产函数变体确认可产生；③实际运行断言，形成已观察到的“能区分／不能区分”性质表。**三分钟演示：**两个内容不同但同样通过的具体结果并排展示，点击“成员身份”定位目前没有区分它们的断言；不宣称穷尽所有错误。
- **近邻与待验证差异：**[Oracle Gap](https://squareslab.github.io/materials/jainOracleGap.pdf) 和 [Where Tests Fall Short](https://mgnmtn.github.io/assets/pdf/Maton2025.pdf) 已深入研究测试检查不足。差异假设只是面向结果性质的可行见证解释；若退化为 mutation score 换皮，该方向没有站住。**最大阻碍：**候选结果可能不满足真实业务不变量。**工期：**5–8 天，限定纯函数、列表／字典结果和少量变体规则。
- **最便宜证伪：**8 对代码覆盖相同但断言不同的测试，CPU 预算 45 分钟。正控只检查长度；负控完整比较成员和数值，同时加入无关字典键顺序变化。若性质表不能反映断言加强，或把不可行结果当盲区，停止扩展。

**N5｜失败信息折叠图：哪些不同原因最后变成了同一个结果？**

- **问题与最小例子：**“确实没有记录”“文件格式错误”“读取失败”都最终返回 `[]`。调用者从这个返回值还能分辨什么？**输入：**函数及调用链、可控的异常注入点，以及明确选定的观察边界，例如返回值或返回值加错误码。
- **机制，三步：**①为正常空结果和不同异常路径附上仅用于分析的来源标签；②追踪它们穿过 catch、默认值和包装函数后的实际输出；③找出不同来源首次被映射成相同可观察结果的位置。**三分钟演示：**三条路径在 `except: return []` 汇合；把错误码纳入观察边界后，仍可区分的路径重新分开。
- **近邻与待验证差异：**[Exception Miner](https://leopoldomt.github.io/assets/pdf/2024-sbes.pdf) 已研究异常反模式；[Crossing](https://pypi.org/project/crossing/) 已包含数据丢失和异常语义测试。待验证差异是“相对于某个调用者观察边界的信息损失”，不是给宽泛 catch 再加警告。**最大阻碍：**信息可能保留在日志等其他通道；必须限定观察边界，不能说全系统丢失。**工期：**5–7 天，Python 同步函数和受控异常路径。
- **最便宜证伪：**10 条小调用链，CPU 预算 30 分钟。正控为多个失败与正常空结果合并；负控为保留不同错误码、重新抛出异常、明确记录在选定输出通道中。若调整观察边界后报告仍不变化，机制不成立。

**N6｜功能组合见证：哪个最小功能集合共同制造了这个行为？**

- **问题与最小例子：**CSV 的 trim 插件单独不减少行，dedup 插件单独也不减少 `"A"` 与 `" A"` 两行；同时启用才变成一行。开发者想知道某个输出变化由哪些功能共同造成。**输入：**可独立开关的纯处理插件、合法组合约束、固定输入，以及行数等明确观察量。
- **机制，三步：**①执行基线和受限功能组合；②求导致指定输出变化的最小充分功能集合；③对相关记录做切片，连接到共同作用的转换与判断代码。**三分钟演示：**四格展示空集、trim、dedup、二者同时启用；只在最后一格出现合并，并给出两行数据的去向。
- **近邻与待验证差异：**[TypeChef](https://github.com/ckaestne/TypeChef) 已做变体分析，功能交互研究也很成熟。差异假设是以一个具体结果为中心，给出最小功能集合及数据见证；不能声称首次发现组合效应。**最大阻碍：**组合爆炸及插件不可隔离；最小集合也不保证唯一。**工期：**8–12 天，3–6 个确定性 Python 插件；1–2 个月再研究更大组合空间。
- **最便宜证伪：**4 个插件、16 种组合，CPU 预算 1 小时。正控为 trim 与 dedup；负控为两个只改变不同列、不会改变所选行数的插件。人工穷举得到全部最小集合；若搜索漏掉并列最小解释，必须明确降为不完整结果。

**N7｜同一个值的四方会诊：规范、接口、mock 和消费代码在哪里分叉？**

- **问题与最小例子：**OpenAPI 允许 `discount=0`，真实接口返回零，mock 只生成正数，页面 `discount || "N/A"` 把零显示为缺失。开发者要看的是同一个值穿过四种表示后的证据，而不是四份互不相通的报告。**输入：**一条 API 的 schema、已保存响应、mock 规则和一个明确的消费表达式。
- **机制，三步：**①从 schema 与现有响应抽取零、空值、缺字段等边界输入；②把同一见证送过可执行的 mock 生成约束和消费表达式；③按“规范允许性、接口实值、mock 是否覆盖、消费后结果”生成并排记录。**三分钟演示：**点选零值，一眼看到四列；明确区分 mock 没覆盖与 mock 违反规范。
- **近邻与待验证差异：**[Specmatic](https://specmatic.io/) 已做契约、mock 和接口一致性。差异假设是把传输层边界值进一步连接到消费代码中的具体含义折叠，并以同一见证串联；可能是工具集成贡献。**最大阻碍：**schema 对领域含义通常表达不足；不能自行判定零必须显示为零。**工期：**7–10 天，一个 REST endpoint、JSON Schema 子集、纯 TypeScript 消费表达式。
- **最便宜证伪：**12 组值状态，CPU 预算 45 分钟。正控覆盖零与缺失合并、字符串与数字分叉；负控包括 `??` 保留零、规范明确禁止零、明确批准的展示格式。若工具混淆“没测到”“违反契约”和“显示变换”，方向失败。

**N8｜AI 代码的选择余量：哪些决定确由需求推出，哪些只是这次实现选择？**

- **问题与最小例子：**需求规定“按分数降序返回前 k 项”，AI 代码额外采用按 ID 打破同分；这条规则是否由需求推出？**输入：**AI 生成的实际函数、原始需求、开发者确认的少量可执行约束，以及有限的候选决策语法；不把自然语言自动翻译当无误真相。
- **机制，三步：**①从实际代码定位 tie-break、隐式排序、额外过滤等可表达的决定；②在有限模型中检查每项决定是否被已确认需求蕴含，或只是其中一种允许选择；③对非蕴含决定生成满足相同约束、却产生不同输出的替代见证。**三分钟演示：**在实际代码旁看到“降序由需求约束；同分按 ID 是未指定选择”，点击得到两个合法但不同的 top-k 结果。
- **近邻与待验证差异：**[AssureCode](https://arxiv.org/abs/2610.29758) 和 [CONTRA](https://arxiv.org/abs/2610.01769) 均为 2026 年预印本；CONTRA 已通过候选程序的行为差异支持澄清。这里的差异假设只保留为“对实际交付代码逐项提供需求蕴含状态”的审查工作流，双程序见证本身不能算新算法。**最大阻碍：**抽取的决定可能过细，或确认形式约束的成本超过收益。**工期：**8–12 天，排序、过滤等 5 类纯函数；更广泛代码需 1–2 个月探索。
- **最便宜证伪：**8 份人工可核对的有限需求，其中 4 份故意留白、4 份完整指定，CPU 预算 1 小时。正控为同分规则留白；负控明确规定按 ID 排序，并加入互相矛盾的需求检查能否提示“约束无法同时满足”。若所谓替代方案违反显式约束，或已规定的决定仍标成任选，核心解释无效。

**N9｜聚合单位透视：这个平均值究竟在平均订单，还是订单行？**

- **问题与最小例子：**订单金额为 100、200，分别关联 1、3 条明细；JOIN 后 `AVG(order.amount)` 得到 175，订单平均值则是 150。开发者想知道是哪一步改变了每条原始记录对结果的权重。**输入：**SQL、可重放的小表、用户声明的原始实体键；不从列名推断“正确平均对象”。
- **机制，三步：**①给原始实体附上分析用身份并重写受支持查询；②在 JOIN、FILTER、GROUP BY、AGGREGATE 处记录实体保留情况和重复权重；③把最终 SUM／AVG 分解成“哪些实体、各贡献多少、分母是什么”。**三分钟演示：**点击 175，显示 `100×1 + 200×3` 除以 4，再展示以订单为单位的候选对照，不自动修改 SQL。
- **近邻与待验证差异：**[GProM](https://github.com/IITDBGroup/gprom) 已提供数据库 provenance。差异假设是把中间表的实体重复度压缩成易理解的聚合公式，展示分析单位何时改变；溯源重写本身不新。**最大阻碍：**DISTINCT、NULL、多层聚合会使简单贡献分解失真。**工期：**7–10 天，SQLite 的内连接、过滤、SUM 和 AVG，暂不支持 DISTINCT。
- **最便宜证伪：**8 条小查询，用手算有理数答案作对照，CPU 预算 30 分钟。正控为一对多连接；负控为一对一连接和明确按明细加权的聚合。检查解释公式是否精确复原查询值，且同一事实在不同意图下不自动变成 bug。

**N10｜论文数字的分母地图：两根柱子是否建立在同一批观测上？〔大胆方向〕**

- **问题与最小例子：**方法 A 在 80 个成功运行样本上正确 72 次，图中为 90%；B 在全部 100 个样本上正确 85 次，为 85%。两根柱子的纳入规则不同；把 A 的失败样本纳入会得到另一种比较。**输入：**notebook、完整原始结果表、样本 ID、绘图调用；只解释已有记录，不猜测缺失试验。
- **机制，三步：**①跟踪受支持 pandas 操作对样本成员和权重的改变；②给图表数据点附上分子、分母、排除条件和来源 cell；③比较两点的成员集合与权重，按用户选定的共同集合重算可定义的结果。**三分钟演示：**点两根柱子即显示“72/80 与 85/100”；切换到共同成功集合或全样本口径时，缺少的数据明确显示不可计算。
- **近邻与待验证差异：**[noWorkflow](https://github.com/gems-uff/noworkflow) 已追踪 Python provenance；[Vizier](https://www.cs.uic.edu/~bglavic/dbgroup/assets/pdfpubls/BB19.pdf) 已把 notebook、数据调试与 provenance 结合。差异假设是以“论文中相互比较的结果”为单位，直接暴露成员集合、权重和可重算范围，而不是让作者自行读整张 provenance 图。**最大阻碍：**仅追踪样本 ID 不能恢复指标含义，自定义指标与多次采样权重也很难。**工期：**9–12 天，筛选、连接、分组和比例指标；1–2 个月探索真实论文结果链。
- **最便宜证伪：**6 本极小 notebook，每本输出两根柱子，CPU 预算 1 小时。正控包括不同分母、相同分母但不同成员、重复采样权重；负控为相同样本仅重排行序，以及显式声明为不同条件总体的比较。若只能报样本数、不能解释成员差异，或为不存在的样本编造结果，高收益假设失败。

**N11｜构建缺席解释：源码里明明有它，为什么产物里没有？**

- **问题与最小例子：**源码包含 codec 实现，但构建配置没有纳入该源文件；另一个 codec 已编译，却没有从静态库中被链接进最终产物。开发者要区分这些完全不同的缺席原因。**输入：**一个 C/C++ 构建目标、编译数据库、实际命令、对象文件与 linker map，以及目标符号。
- **机制，三步：**①把目标符号连接到源文件、预处理结果、对象文件与链接记录；②寻找证据链中第一个缺席边界，区分未纳入、被条件编译排除、未提取、被回收；③输出可检查的证据，必要时在限定构建配置中给出一个重建对照方案。**三分钟演示：**点击两个都“搜不到”的符号，看到不同原因和各自对应的 CMake 条件或链接记录。
- **近邻与待验证差异：**[Bloaty](https://github.com/google/bloaty) 已把二进制体积归因到符号和编译单元；[CrossLink](https://conf.researchr.org/details/icpc-2026/icpc-2026-tool-demonstration/2/CrossLink-A-Tool-for-Cross-Language-Java-C-C-Code-Comprehension-) 已分析跨语言依赖。差异假设是解释预期源实体为何缺席，以及缺席发生在哪个构建边界。**最大阻碍：**LTO、动态加载、缺失构建记录会破坏可靠解释；此时必须输出未知。**工期：**8–12 天，固定 Clang/ELF、关闭 LTO、静态链接。
- **最便宜证伪：**4 个微型构建目标×4 种缺席原因，CPU 预算 1 小时。正控分别植入四种原因；负控为符号已存在、仅隐藏可见性，以及故意删除必要记录。若工具把“没有证据”当“已经证明不存在”，不应继续做泛化。

**N12｜补丁适用边界：相似代码需要同一修复，还是有意保持不同？**

- **问题与最小例子：**一个导入器从 `split(',')` 改成正确处理引号的 CSV 解析；相似代码中既有另一个 CSV 导入器，也有显式禁止引号的简单协议解析器。哪处遗漏值得查看，哪处不能照搬？**输入：**一份补丁、开发者指定的相似函数候选、各调用上下文的显式输入约束及相关测试。
- **机制，三步：**①提取补丁前后已证实的行为变化，形成可执行对照；②把见证映射到相似函数，并经调用上下文检查是否可达；③在临时函数副本上比较应用补丁前后的行为，报告“可重现同类差异／输入域排除／证据不足”。**三分钟演示：**两个长得很像的解析器，一个可由合法 CSV 输入复现问题，另一个因明确禁止引号而不适用。
- **近邻与待验证差异：**[ReDeBug](https://users.ece.cmu.edu/~jiyongj/papers/oakland12.pdf) 已找未修复克隆；[SemaDiff](https://arxiv.org/abs/2607.13111) 已考虑未修改调用者和成对测试。差异假设是以补丁的适用输入域解释哪些相似片段应继续核查，尤其把合理分歧作为一等结果；不是新克隆检测器。**最大阻碍：**函数对应和可达性约束不完整，自动移植补丁可能改变无关行为。**工期：**8–12 天，Python 解析函数、小型 AST 变化、人工给定候选集合。
- **最便宜证伪：**6 组补丁，每组包含遗漏同类修复、合理不同和信息缺失各一例，CPU 预算 1 小时。正控需要通过真实调用上下文复现；负控明确限制输入域，另加只有语法相似但语义不同的片段。若只能凭相似度给出同修建议，核心目标未达到。
