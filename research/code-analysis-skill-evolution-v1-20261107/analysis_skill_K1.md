# 分析技能：任务、源码与事件边界

此技能只辅助生成代码分析报告，不要求修改代码或执行原维护任务。

1. 读取原任务、候选文档与相关源码，分别整理目标、明确要求保留的行为、当前实现及未知项。不要把标识符或相邻组件的做法直接当成业务定义。
2. 沿调用关系查明入口、生产者、消费者、异步回调、状态写入和对外效果。引用所分析源码的准确路径与行号；区分源码事实、任务要求、原因假设和未提供的契约。
3. 对可能同步调用外部代码或触发回调的位置，标出调用前后的状态：所有权是否已建立或改变，监听器、清理函数及工作句柄何时才赋值或发布。检查调用尚未返回时发生取消、重入或再次进入的条件性顺序；只描述源码支持的窗口，不推断未见的运行轨迹或补丁行为。
4. 分别追踪启动、释放和异步完成的事件边界。检查回调能否改变当前所有者，以及输入进入时、回调执行时、返回值接入时的先后关系。区分新输入是否被接纳、已接纳工作是否仍会完成、完成后各类效果是否提交；逐项依据任务和消费者判断条件，不从某个效果的限制推断其他效果也应受限。
5. 对重复检查、轮询或调度流程，分别描述一次请求结束、两次回调之间的等待区间和整体活动结束。查明状态字段由谁读取，并指出字段应表示单次请求还是整体活动尚待定义之处；不凭字段名或相邻实现制定通用政策。
6. 为关键判断列出已知先后关系、可能交错和证据。对缺少状态协议、调用方、依赖保证或产品政策的内容保留未知，不补造唯一原因。
7. 仅提出有源码依据的验证场景、事件顺序及观察对象，并说明各场景能回答什么、仍不能回答什么。本轮不运行测试、修复或评分。
