actual prompt differences separately from downstream repair results.

## What was reviewed

The execution agent read the original training tasks, visible documentation and
source, then produced per-rule label annotations. `label-review.json` in each
experience directory records the source hashes, exact single-line quotes, label
reasoning, evidence basis and unassigned-label boundaries. Native package labels
are the union of these explicit per-rule findings.

These are new AI-assisted executor annotations, **not** additional experimental
model extraction, reflection or judge sessions. They are not independent expert
approval or a ground-truth classification dataset. Raw legacy reflection objects,
translations, previous failures, outcomes and limitations remain unchanged.
The annotating agent already knew the historical labels and broader experiment
context; this is not a blinded classification exercise. The audit exposes the
actual source grounds instead of claiming that exposure was absent.

The recoding interface validates an annotation sheet; it does not decide labels
from a case ID, old T class, API name or score. Administrative source selection
and lineage paths remain audit metadata, outside runtime classification/ranking.
No test trajectory, test patch, test score, reference patch or evaluator assertion
was used as a source anchor for classification.

## Important label boundaries

- Listener/admission publication before synchronous startup is O/L, not an extra
  R readiness prerequisite. No audit-completion-before-return B policy is added.
- The shared-work R label comes from network/focus entry conditions. Static
  record-versus-controller ownership in its fourth rule is L, not automatically I.
  I is supported separately by old-attempt completion binding; A by the explicit
  multiple-observers/one-fetch cardinality requirement.
- The document B labels include an explicit preservation inference based on the
  task, synchronous APIs, original immediate writes and persisted reopening.
  They are not presented as verbatim README settlement deadlines or a uniquely
  required flush implementation.
- Visit/attempt retirement is not automatically F. No within-retained-owner
  result-revision obligation was established for these experience rules, so no F
  experience was fabricated. This does not prove that F mechanisms are absent
  everywhere in the source or future tasks.
- A is tied to actual accepted-audit retention, explicit single shared execution,
  latest-only bursts or retained receipts, not generic regression equality.

## Implemented and verified

`experience_recoding.py` creates an immutable candidate only after checking
review scope, codebook fingerprint, all rule identities, valid label codes,
original source roles/hashes/quotes and the complete assigned/unassigned label
partition. It does not edit policy text or activate any version. The CLI exposes
`experience-memory recode`, plus repeated `--label` filters on list/search.
Multiple labels are an intersection; applicability and expert gates remain
separate from browsing and organization.

Mechanical checks and exact citations cannot prove that a label's meaning is
supported. The per-rule AI judgments remain reviewable and rejectable.

Offline verification: 66 checks passed (6 recoding, 17 memory, 6 expert gate,
11 lifecycle, 4 native adapter, 14 existing routing and 8 reused runtime/archive
checks). Raw logs and their program-summed counts are in `VALIDATION.json`.
The label-intersection CLI was also exercised against the actual shared store:
B plus I returns the deferred-boundary candidate, still unactivated.
The final derivation check caught a relative-versus-absolute review-path digest
difference. Canonicalizing the review path fixed it; a dedicated regression test
now verifies identical derivations. Existing candidate records did not change.

## Not executed and not claimed

No model sessions, repair replay, external rescoring or expert activation were
performed. Fresh repair effectiveness is unknown, not zero and not a behavioral
failure. Existing outcome references are retained as historical audit evidence,
not counted as new native-taxonomy validation. In particular, English translation
wording does not inherit proven effectiveness from an earlier-language result.

No classification-accuracy, seven-class coverage or generalization claim is made.
The source cases are already exposed. No next case, reflection, test batch,
production registry update, dependency installation or Git commit was started.
