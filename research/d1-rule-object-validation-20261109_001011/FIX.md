本版在独立目录修复反思输出协议；保留旧原始输出、旧拒绝决定及暂存文件。

模型不再输出完整经验全文、规则编号或规则逐字引用。唯一正文来源是 `rules[].body`。Python 按原列表顺序生成 R01 起的编号，加固定类别标题后拼接原始正文；不改写句子，不补证据或业务政策。渲染文件在 `derivation.json` 中明确标为程序派生产物，不冒充另一份原始模型输出。

`requires` / `excludes` 使用原 predicate 词典，并将全部定义加入反思输入。每个选中的机制前提另有状态、证据 ID 与解释。每条规则的 `conditions` 是支持适用性的证据 ID，不是机制 key 或自然语言条件；解释只进入 `explanation`。交付维护模型的只有规则正文与机械编号/标题，不包含证据元数据。

schema 根据冻结账本生成：support、conditions 和 counterevidence 只允许当前有据条目的 ID，未知或原因假设不能作为已知适用依据；preserve 只允许现有约束 ID；requires/excludes 只允许现有 predicate key。要求完整保留约束和已知反例。未明确证实的必需机制、未知排除条件都不能通过。类型/长度使用当前后端已有的结构化 JSON 对象方式，无内嵌 JSON 字符串。

机械约束不证明语义：执行 Agent 仍要逐规则核查证据是否支持规则、当前机制条件是否成立、因果声称是否越界、是否保留已知正确行为和反例。核查绑定模型对象、账本与派生正文摘要，明确为 AI 辅助核查，不冒充人工批准。

复用上一版 provenance/feedback 函数、运行器、隔离、请求计量、失败归档和评分交接。仅将旧重复全文候选核查替换为单一规则对象协议，并适配阶段控制器。没有导入旧调度器，没有新增模型探测或依赖。

离线检查包括合成夹具、旧失败原始对象、显式标记的派生夹具、false 期望/原有成功/退步/未知结果，以及部分输出和异常归档。旧失败对象仍被拒绝，没有被转换成新候选。具体测试结果见 `offline-checks.log` 和 `freeze.json`；基线等价条件见 `condition-audit.json`。

原始响应在解析前由运行器保存。完整模型对象、校验结果、派生正文和逐规则依据分别归档并记录摘要。若模型未完整结束，部分输出保留在运行器归档，不会补全或评分。
