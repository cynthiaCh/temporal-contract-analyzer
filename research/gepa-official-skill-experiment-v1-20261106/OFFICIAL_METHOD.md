# Official method alignment

Sources: [official repository](https://github.com/gepa-ai/gepa), [official paper, arXiv:2507.19457v2](https://arxiv.org/abs/2507.19457). The installed full package is pinned to commit `8e9ae9ed063f6a0259c93db595b96953fdab0e6d`, metadata `0.1.4`. `environment/official.json`, `pip-freeze.txt`, wheel and SHA record identify the environment. The source checkout remains unmodified; installed implementation files are hashed in protocol.json. No production dependency installation.

The real entry point is `gepa.optimize`, called once by `gepa_adapter.optimize`. `Adapter.evaluate` invokes the original autonomous workspace runner and trusted external scoring. `Adapter.make_reflective_dataset` constructs trace-grounded train-only feedback. It implements the official adapter protocol structurally; `EvaluationBatch.num_metric_calls` explicitly counts real task executions. No custom proposal/search algorithm is supplied.

The installed engine, not the adapter, selects parents from the per-instance validation Pareto frontier, selects the single component, samples train minibatches, calls its reflection proposer and parser, compares parent/child minibatch scores using strict improvement, admits improvements, evaluates admitted candidates on full val, maintains the candidate pool/parents/frontier, and returns the highest validation mean (earliest index tie). `official-events.jsonl`, `gepa-run/gepa_state.{json,bin}`, `candidates.json`, `pareto/instance_front.json`, and `official-result.json` retain the native state and outcome. `candidates/` additionally preserves every parsed proposed text, including rejected texts, with validation and boundary review. A boundary review checks leakage/scope only and never rewrites a candidate or selects by expected effectiveness.

Reflection uses the official `StatelessReflectionLM` wrapping a callable and its `InstructionProposalSignature` parser. The callable sends the fully rendered GEPA prompt to the existing authenticated Codex CLI with `gpt-6-sol/low`, in an empty read-only isolated workspace. Fixed reflection template is supplied through the documented `reflection_prompt_template` API. This is a constrained skill-optimization adaptation, not an exact reproduction of the paper's model, meta-prompt or benchmark. We do not equate installing the package with reproducing the paper.

Merge is implemented upstream but explicitly disabled (`use_merge=False`); no merge should be claimed. Alternative frontier modes, objective-aware selection, context-aware reflection and `optimize_anything` are not used. Formal evaluation cache is disabled because executions are stochastic. Checkpoints are written but formal automatic resume/replay is refused; a no-model synthetic run validates official resume behavior separately. Unused budget is retained.

`max_metric_calls` is checked by the engine at iteration boundaries. The adapter therefore adds a conservative reserve of six real tasks before a new iteration (parent2 + child2 + potential val2) and checks the ledger before every batch/launch. Reflection callable invocations and underlying requests are separately metered; pre-request OS supervision prevents an unexpected seventh provider request. The execution-agent request meter is passive and adds no evidence/Stop/continuation rules. The prior experimental ReAct controller is absent.

Absolute budgets are optimization tasks24, reflection underlying requests6 and final test tasks12. Synthetic optimizer/parser/calibration runs use no real model and no maintenance-agent execution. They are not counted as efficacy evidence. Final result/selection is frozen before any test execution; test inputs/results are never supplied to the adapter or reflection callable.
