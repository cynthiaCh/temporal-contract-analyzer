# Temporal contract skill: completion, ownership, and effects

Purpose: complete the original maintenance task. Use this skill to find timing and ownership mistakes in the requested behavior. It does not add product requirements or replace implementation with a contract discussion.

S1 Applicability. Apply when work can complete after its initiating access, operation, or consumer changes; when a callback can change ownership during another call; or when one result feeds effects with different lifetimes. Otherwise, briefly record why these conditions are absent and continue the maintenance task.

S2 Establish evidence. Read the entry point, producer and decoder or dependency, subscription and startup order, completion path, ownership transitions, cancellation and cleanup, and every affected effect consumer. Read adjacent consumers of any shared helper. Use source locations when explaining conclusions. Separate task requirements, source facts, hypotheses, and unavailable evidence. Treat retrieved excerpts as incomplete. Do not infer a guarantee from a name, a comment alone, or a passing local check.

S3 Write the contract before changing code. Identify the distinct identities the project actually uses: resource, access or visit, physical attempt, and individual input or accepted result. Trace when each is created, captured, replaced, and retired. For each effect, state which identity must still be valid when it runs. Consider durable history, audit or queue records, notices, diagnostics, and current display separately. An effect that belongs to an already accepted attempt may have a different validity rule from a display tied to the current visit. Do not turn listener removal, future-input cancellation, or display hiding into cancellation of already-started work without source or task support.

S4 Trace the whole call stack. If startup, subscription, decoding, cancellation, detachment, or publishing can invoke a callback synchronously, follow what that callback can change before the outer call resumes. After each reentrant call, check that the outer call still owns every effect it is about to perform. Also check work accepted before a release whose completion occurs afterward. Compare the identity needed for recording with the identity needed for display; avoid a single guard merely because both effects share a callback.

S5 Compare concrete event orders using project-supported controls. Include ordinary completion, delayed completion after close or switch, same-resource reuse, and replacement or retry where present. Include startup emission and synchronous reentry where supported. For asynchronously decoded ordered results, compare normal and reversed settlement. Observe each effect independently: retained records, notices, diagnostics, visible state, and cleanup. Check that a later accepted full result cannot be visually replaced by an older one when the task requires ordering, while preserving any independently valid history. Do not invent input schemas or timing guarantees.

S6 Preserve surrounding behavior. Keep public interfaces and unaffected consumers of shared helpers. Check whether a change to subscription or startup order changes bootstrap delivery for another consumer. Check whether cancellation or replacement changes queue, audit, notice, or cleanup behavior. Make the smallest change supported by the task and source evidence. If no change is justified, explain why; if essential evidence is unavailable, state what remains unresolved.

S7 Verify the repair as a maintenance task. Run relevant available checks and inspect their actual output. Add focused checks only for meaningful uncovered orders and effects. A local harness proves only the paths it drives: include reentrant ownership changes and pending completions across release or replacement when applicable, as well as ordinary use and subsequent reuse. Revise the implementation when a check exposes a mismatch. Report failed or unrun checks and limits explicitly. Completion requires a supported code repair or an evidence-based no-change conclusion, not a successful self-written smoke check or a prose contract alone.
