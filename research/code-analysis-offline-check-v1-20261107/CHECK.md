## 2. 新输入接纳的对照，具体漏在哪里？

【问题】
报告已找到入口、切换和迟到完成，但没有把它们串成“切换后再来一条新输入”的独立查证。

【报告怎么说】
- “选择操作在 enqueueTransfer 返回前也尚未给 visit.handle 赋值；外部回调可能改变 current。”（[a06:10](../code-analysis-skill-evolution-v1-20261107/runs/a06/report.md)）
- “已收到事件的 Promise 完成后仍调用 record，再调用 receive；只有 receive 在执行时检查访问是否仍当前，因此历史记录和面板显示的提交条件不同。”（a06:10）
- “这区分了包被接收、解码完成及各效果提交。”（[a08:11](../code-analysis-skill-evolution-v1-20261107/runs/a08/report.md)）

【源码／标准怎么说】
入口是[start/emit派发](../code-analysis-skill-evolution-v1-20261107/materials/U1/candidate/src/progress-source.js)（26–30行）→listener→decode（progress.js:3–7）。切换会改变current，句柄在enqueue返回后才接入（panel.js:14–24）；record无current判断，receive有（queue.js:11–15）。K1第4步已明确要求区分“新输入是否被接纳、已接纳工作是否仍会完成、完成后各类效果是否提交”。标准R3/A3/A4要求分开核查这些关系。

**已覆盖：**两份报告都写了入口与切换；迟到完成的history/display区别也有源码依据，不能说它们“完全未识别”。

**漏掉的连接：**没有单列“归属已改变、旧监听尚未有效移除时，新包进入listener/decode/record会怎样”，也未与“切换前已开始解码，之后才resolve”作同一组对照。`initialPacket`可为函数、在派发前执行的入口也未展开。

**版本及未知限制：**原始progress.js先start后注册；该次注册前初始包不会进入这个新监听器。标准历史故障涉及提前监听的补丁，不能套到本轮原始代码。接纳资格的精确政策、具体窗口是否可达和宿主实际调用栈仍需证据。本项不要求报告复述历史评分，更不要求其凭未决政策断言一律禁止历史记录。

**已确认问题，仅限报告缺少上述源码对照查证。**不是已证明当前原始版本存在历史故障，也不是已证明业务要求判断错误。可能是分析集中在返回值/取消和结果提交，具体原因未知。

## 3. retry是指导被删了，还是验证建议不够明确？
