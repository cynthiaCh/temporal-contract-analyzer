# 跨案例共同评价维度（尚无评价结果）

仅用于将来比较分析报告，本轮没有生成报告、不预先认定模型弱点。草稿待确认项不能当成确定错误扣分。逐项记录“满足／部分满足／不满足／证据不足”，附报告原句、源码位置与规范来源；不累计质量总分，不用局部覆盖抵消关键事实错误。

| ID | 共同维度 | 未来可检查的证据 |
|---|---|---|
| G1 | 事实和引用正确 | 原始版本、路径、行号、入口／回调／写入实际对应；不能引用补丁替原版证明。 |
| G2 | 源码事实与业务要求分开 | 任务、项目文档、注释、测试预期和假设分别标来源；代码存在不自动说明业务合法。 |
| G3 | 关键事件关系 | 描述先后及前提，区分原始实现顺序、目标契约情境和未证实可达性。 |
| G4 | 身份、阶段与效果 | 按案例区分消费者／批次／visit／操作身份及入口、完成、持久化、归档、显示；不强加每例都拥有相同对象。 |
| G5 | 未知保留准确 | 缺少什么证据说清楚；未知不等于安全或已证明缺陷，也不算确定错误。 |
| G6 | 验证建议对应目标关系 | 建议可区分关键顺序并覆盖保留行为，不以执行某命令替代具体行为验证，不要求唯一补丁。 |

接受同义、等价和跨段落表达，先阅读全文再判遗漏。各条分开记录“未写出／写错／合理未知”；部分覆盖说明覆盖及缺口，材料不支持的要求标证据不足。引用有误与业务判断有误分开。不可评价项说明原因，不以更多字数、更多提醒或条目总数判改善。

三例为开发来源，C2/C3 存在辅助模板关联；未来统计不得把同源变体、重复报告或条目当独立案例，不预填跨案例结果，不据分析质量推断代码修复。
