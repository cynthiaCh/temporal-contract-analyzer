# V8 训练与配对测试方案

本轮训练恢复 V8 的有效配方，使用已选的 train10，模型 `gpt-6.1-sol / medium`，原始 16 条已审核经验快照，按顺序在线积累 provisional 经验。每例最多 3 次 Action，每次最多 24 requests / 600 秒，整例最多 132 requests。失败后保留 diagnosis；Action 接收最新反馈和更新的 Contract，不附加累计诊断解释。采用 V8 原有 source-bound routing，跳过新增的独立语义选择模型阶段。训练通过要求公开检查和独立 Gold 同时通过。

沿用原有只读输入、评分隔离、证据校验、Contract 写入被拒后的单次纠正机会。历史 V8 目录不改写。已有机制复用 V8 公开例子；review、workspace 和 download 依公开 API 增补例子，并记录来源。这是 V8 配方在新 train10 上的复用，不是旧 25 例的精确复现；历史 24/25 不能作为本轮成绩或预期。

## 主测试：判断本轮训练是否有增益

固定现有 test10，不再依据本轮成绩换题。每例分别运行两组：

| 组别 | 经验 | 用途 |
| --- | --- | --- |
| A | 原 V8 已审核 16 条，冻结 | 训练前基线 |
| B | 同一 16 条 + 本轮 train10 中审核通过的新经验，冻结 | 测量新增训练的收益 |

两组使用同一模型、原始 L task/base、AST、Contract 校验策略、V8 source-bound 检索、工具权限和预算；每例恢复相同原始代码，两个组之间完全隔离。两组都不注入训练阶段生成的 VISIBLE_CHECKS.md、诊断或任务修复记录。原仓库自带公开测试可以在 Action 会话内运行。

每例只有 **一次 Action（24 requests / 600 秒）和一次最终提交**；会话内可以自行运行公开测试并改代码。最终提交后由独立 Gold 评一次分，不回传给 solver，不诊断、不追加 Action、不抽取经验，不跨测试例更新经验。Contract 仅根据公开输入校验，沿用测试侧最多 3 个版本的公开审查，不能接触 Gold。传输故障只能使用原有有界重试；失败的模型输出或 Gold 失败不能用重跑择优替换。

主要报告 A/B 各自 Gold 通过数 / 10、逐例胜负变化、execution_invalid 数和原因、请求数、tokens 和耗时。主分母始终为 10；invalid 单列且计为未解，不能只报有效案例的比例。有余力再加无经验 Auto-Contract 和原始 L 两组作为辅助对照；它们不能替代 A/B，否则无法区分原 16 条和本轮新增经验的贡献。

## 冻结与启动顺序

1. 完成本轮 train10，保留所有成功、三次失败和中止轨迹。
2. 只用训练轨迹审核候选经验；未经审核的 provisional 不进入正式测试。若另做 provisional 探索组，单独命名、冻结并报告。
3. 冻结 A/B 快照与 SHA、测试输入、模型、代码和预算。增加独立的 testing source-bound 检索配置并验证；不能把 training_recipe 打开到 testing。当前 JSON 是预注册方案，尚未启动测试，也未声称现有默认测试器已经采用 V8 检索。
4. 跑两组 test10 后统一分析，不根据单例分数调整经验、prompt 或再挑 case。后续修改只能算新的探索实验，不能覆盖本轮记录。

## 结论范围

这批测试例是按历史低通过率挑选、与训练机制配对的同族任务；不是未接触过的盲测。原 16 条经验也可能来自同族历史任务。因此主结论是“同族机制迁移及本轮新增经验的增量效果”，不能宣称全新任务泛化。训练使用公开例子而测试使用原始 L，应明确报告这一输入差异。正式未见泛化需要额外、预先冻结且从未用于训练/选题的保留集。

机器可读配置见 `testing-protocol-v8.json`。本次只启动训练；测试在经验审核与快照冻结后另行启动。
