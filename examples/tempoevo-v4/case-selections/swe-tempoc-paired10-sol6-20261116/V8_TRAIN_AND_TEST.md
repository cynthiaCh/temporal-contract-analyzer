# V8 经验构建与全量经验单组测试方案

本轮训练恢复 V8 的有效配方，使用已选的 train10，模型 `gpt-6.1-sol / medium`，原始 16 条已审核经验快照，按顺序在线积累 provisional 经验。每例最多 3 次 Action，每次最多 24 requests / 600 秒，整例最多 132 requests。失败后保留 diagnosis；Action 接收最新反馈和更新的 Contract，不附加累计诊断解释。采用 V8 原有 source-bound routing，跳过新增的独立语义选择模型阶段。训练通过要求公开检查和独立 Gold 同时通过。

沿用原有只读输入、评分隔离、证据校验、Contract 写入被拒后的单次纠正机会。历史 V8 目录不改写。已有机制复用 V8 公开例子；review、workspace 和 download 依公开 API 增补例子，并记录来源。这是 V8 配方在新 train10 上的复用，不是旧 25 例的精确复现；历史 24/25 不能作为本轮成绩或预期。

## 主测试：完整已审核经验快照，单组运行

固定现有 test10，不再依据本轮成绩换题。每例只运行一组：原 V8 已审核 16 条，加本轮 train10 中已审核通过的 2 条，共 18 条，冻结后供检索。这里的“全量”指本批已审核经验全集，仍按任务匹配适用经验，不是将所有条目强行注入 Prompt，也不自动混入其他经验来源。

不再安排原 16 条的 A 组、无经验 Auto-Contract 或原始 L 对照组。已经产生的旧 A/B 轨迹、快照和结果保持原样，不能回写成新的单组结果。单组结果用于描述当前完整配置的表现，不能单独证明新增经验的因果增益。

使用同一固定模型、原始 L task/base、AST、Contract 校验策略、V8 source-bound 检索、工具权限和预算。每例从原始代码开始，不注入经验构建阶段生成的 VISIBLE_CHECKS.md、诊断或任务修复记录；原仓库自带公开测试可在 Action 内运行。

每例只有 **一次 Action（24 requests / 600 秒）和一次最终提交**。Gold 在提交后独立评分一次，不回传 solver，不追加修复 Action、不抽取经验，不跨测试例更新经验。Contract 沿用最多 3 个版本的公开审查，共享原 Contract 预算，不能接触 Gold。传输故障仅使用原有有界重试；不能用重跑择优替换失败结果。

报告完整经验组的 Gold 通过数 / 10、逐例结果、execution_invalid 数及原因、实际经验投递、请求数、tokens 和耗时。主分母为 10；invalid 单列并计为未解。不再计算 A/B 胜负或新增经验的配对增益。

## 冻结与执行顺序

1. 经验构建与审核记录保持原样，未审核 provisional 不进入正式测试。
2. 只冻结并执行完整已审核经验快照，共 18 条；核对其 SHA、测试输入、模型、代码和预算。不重新准备 A 组或其他对照。
3. 若远端原 B18 组的冻结快照和协议均一致，保留并沿用其已有结果，不为改组名重新运行；禁止启动剩余 A16 任务。停止旧调度前须核对具体进程和任务状态。
4. 完成后统一汇总，不根据单例 Gold 分数修改经验、Prompt 或挑选 case；后续修改使用新协议和新记录。

## 结论范围

这批任务按历史低通过率挑选，与经验构建任务存在同族机制关系，并非未接触过的盲测。本次报告范围是“完整已审核经验配置在该诊断集合上的表现”，不宣称全新任务泛化，也不将经验构建与测试的通过率直接相减。原同源案例配对清单用于描述选例关系，不代表现在仍执行 A/B 两组测试。
